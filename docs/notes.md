# ctc_controller 学习记录

编写计算力矩控制器时的个人学习笔记：CTC 控制原理、代码分层、C++ 接口设计和 Demo 验证方法。

## CTC 的核心思路

机器人关节动力学可以写成：

```text
M(q)q̈ + C(q,q̇)q̇ + g(q) = τ
```

计算力矩控制（CTC）先用反馈计算期望加速度：

```text
q̈_cmd = q̈_ref + Kp(q_ref - q) + Kd(q̇_ref - q̇)
```

再通过逆动力学计算力矩：

```text
τ = RNEA(q, q̇, q̈_cmd)
```

RNEA 是递归牛顿－欧拉算法，能够根据当前位置、速度和期望加速度计算所需关节力矩，其中包含惯性力、科氏力和重力补偿。

纯位置 PID 主要根据跟踪误差被动修正；CTC 则增加动力学前馈，提前计算完成运动所需的力矩。因此在模型准确时，CTC 更适合高速、高精度和重负载轨迹跟踪，但它不是真正的未知参数自适应控制。

## 项目数据流

```text
TrajectoryRef + JointState
          ↓
PD 反馈计算 q̈_cmd
          ↓
RobotModel::rnea(q, q̇, q̈_cmd)
          ↓
力矩限幅和变化率限制
          ↓
输出关节力矩 τ
          ↓
MuJoCo 推进仿真，得到下一拍 JointState
```

MuJoCo 根据当前 `q`、`q̇` 和 `τ` 求解下一时刻状态。控制器再读取新状态，形成闭环控制。

## 代码分层

### 数据层

三个核心数据结构：

- `JointState`：当前关节位置和速度；
- `TrajectoryRef`：期望位置、速度和加速度；
- `Gains`：反馈增益。

`Safety` 负责工程保护，包括绝对力矩限幅、力矩变化率限制、积分限幅和非有限值处理。

### 模型层

`RobotModel` 只规定逆动力学接口，不绑定具体动力学库。`PinocchioRobotModel` 使用 Pinocchio 实现 RNEA。

这种父类接口加子类实现的方式，使控制器依赖抽象模型，而不是直接依赖 Pinocchio，后续可以替换动力学实现。

### 控制层

`CTCController::step()` 接收当前状态和参考轨迹，计算反馈加速度，再调用模型层得到力矩，最后执行安全限制。

## C++ 接口语法

```cpp
[[nodiscard]] virtual int nv() const = 0;
```

- `virtual`：允许子类重写；
- `= 0`：纯虚函数，使 `RobotModel` 成为抽象类；
- `const`：函数不会修改对象；
- `[[nodiscard]]`：提醒调用者不要忽略返回值。

```cpp
virtual ~RobotModel() = default;
```

父类析构函数必须是虚函数，才能通过父类指针删除子类对象时，先执行子类析构，再执行父类析构。

```cpp
class PinocchioRobotModel final : public RobotModel
```

`final` 表示该类不能继续被继承。

```cpp
static PinocchioRobotModel from_urdf(const std::string& urdf_path);
```

静态工厂函数不需要已有对象，可以直接从 URDF 构造模型：

```cpp
auto model = PinocchioRobotModel::from_urdf(path);
```

## 机器人控制层级

1. **电流环（FOC）**：最底层、响应最快，驱动器根据目标电流控制电机转矩。
2. **速度控制**：适合传送带、旋转平台等要求稳定转速的设备。
3. **位置控制**：适合点位运动，结构简单，但高速和负载变化时跟踪误差可能增大。
4. **力矩控制与 CTC**：直接生成关节力矩；CTC 利用动力学模型提高高速轨迹跟踪精度。
5. **阻抗/导纳控制**：规定机器人与环境接触时的柔顺关系，适合装配、打磨和人机协作。
6. **任务空间控制**：直接控制 TCP 的位置和姿态，需要处理雅可比矩阵和奇异位形。
7. **全身控制（WBC）**：协调多个任务和接触约束，常用于人形与四足机器人。
8. **运动规划**：负责生成无碰撞轨迹，本身不直接控制电机，需要下层控制器执行。

这些并不完全是互斥的控制方式。例如运动规划可以生成轨迹，任务空间控制将其转换为关节命令，CTC 计算力矩，最后由驱动器电流环执行。

## Demo 验证

### Demo 1：高速轨迹精度

CTC 和纯位置 PID 使用同一条 TCP 平均速度为 `0.6 m/s` 的圆轨迹、同一初始状态和同一仿真模型。

每个控制周期计算一次误差。末端位置 RMSE 为：

```text
RMSE = sqrt((e₁² + e₂² + ... + eₙ²) / N)
```

其中 `eᵢ` 是第 `i` 个控制周期中参考 TCP 与实际 TCP 的三维欧氏距离。RMSE 越小，说明整体跟踪精度越高。

### Demo 2：力矩安全限制

机械臂故意推动一个无法穿过的障碍物，使跟踪误差持续存在、控制器不断增大力矩。

- 橙线：控制器计算的原始力矩；
- 蓝线：限幅后实际输出的力矩；
- 红色虚线：允许的最大力矩。

蓝线始终不超过红线且饱和计数大于零，说明力矩限制生效。UR5e 使用的关节上限为：

```text
J1–J3：150 Nm
J4–J6： 28 Nm
```

Demo 2 验证的是安全层，不是柔顺控制或避障能力。
